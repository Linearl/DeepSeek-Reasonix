# Release Notes 写作规范（Fork 发版说明）

> 来源：2026-09-21 发版复盘（对照 FORK-v1.38.3.md / 1205 / 1150 / 1500 四篇提炼）。
> 适用：每次「正式发版」（GitHub Release）与每个时间戳过程包的 notes 写作。

---

## 1. 先分清两种 notes（基线规则不同）

| 类型 | 用途 | 增量基线 | 视角 |
|---|---|---|---|
| **发版级 notes**（GitHub Release 页展示） | 面向所有用户 | **上一个「发布的版本」**（如 1205），不是上一个时间戳包！覆盖自上次发版以来的**全部特性**，包括大特性（协作、技能、性能） | **用户视角**：怎么用 + 效果 |
| 过程包 notes（内部装机验证记录） | 记录一次构建的增量 | 上一时间戳包 | 可偏技术，当变更日志 |

⚠️ 反例（2026-09-21 实锤）：`FORK-v1.38.3-20260920-1150.md` 曾把基线写成上一包 `1140`，导致**多会话协作等大特性全部缺失**——发版级 notes 基线写错 = 用户看不到这段时间做了什么。

## 2. 文件名与 workflow 硬约束

- 文件名 = `FORK-v<包版本>.md`，与包版本同名（如 `FORK-v1.38.3-20260921-1500.md`）。包版本 **精确到分钟**：`1.38.3-YYYYMMDD-HHMM`。
- `release-fork.yml` 查找顺序：**精确名优先** → 找不到才剥时间戳回退 `FORK-v<基线版本>.md` → 再找不到**报错退出**（不会静默用旧 notes）。
- notes 正文**必须**包含一行指向 [FORK-vs-upstream.md](FORK-vs-upstream.md) 的引用；且发版前**差异台账要先加本版表**（workflow 会 grep 检查，缺了直接失败）。

## 3. 发版级 notes 的结构模板（七段）

```markdown
# Reasonix Fork 桌面版 v1.38.3-<时间戳> — Release Notes

> 基于官方 v1.38.3，包含 <上个发布版本> 以来的全部更新（约 N 个提交）。
> 数据/会话/记忆目录与官方版完全兼容，覆盖安装即可，无需迁移。
> **Fork 与上游差异全览**：见 [FORK-vs-upstream.md](./FORK-vs-upstream.md)。

## 概览            ← 一段话：本版解决的两三个大问题 + 量化效果
## 🚄 主线一：<用户能感知的大特性>   ← 效果 + 入口 + （1~2 句原理）
## 🤝 主线二：…
## 🧩 技能/内置内容（如有）          ← 表格：技能名 | 触发方式 | 能做什么；依赖声明
## 🔧 其他改进                      ← 一条一行，动词/对象开头
## ⚠️ 升级提醒                      ← 见第 5 节必含项
## 安装                            ← Release 资产 + 覆盖安装说明
```

## 4. 写作视角：用户优先（最重要的一条）

- **先写「你能做什么、体验怎么变」**，再写入口（设置路径 / config 行 / 对话触发语）；**解决方式（原理）压到 1~2 句**，放在效果之后。
- **禁用内部术语**：稀疏索引、头部哈希、MailStore 实例持有、render 表、DAG 重放……一律转译成用户效果（「只加载最近的消息，更早的翻上去再补」）。
- **量化数字必须真实**：来自装机读数或测试（如 `71.7 秒 → 1 秒上下（23 倍）`），不写「大幅提升」。
- **不写任务包编号**（rXXXX）；`task NNN` 只作关联不进正文标题。中文功能描述，动词/对象开头。
- **已知问题如实写**：切出大会话仍 1–3 秒属已知现象、下一版修——诚实比好看重要。

## 5. 升级提醒必含项（逐条过）

1. 覆盖安装即可、目录兼容、无需迁移
2. **存储模式建议**（当前：停留在 v3——双写/仅 v4 未实测）
3. **不要回退到 1.34/1.38.1 以下**（schema 2 单向升级，旧构建拒绝加载，文件不损坏）
4. 已知现象与下一版计划（如保存重放）
5. 未验证项（如 `-race` 未执行）

## 6. 差异台账联动（FORK-vs-upstream.md）

- 发版前在台账**顶部（最新位置）追加本版表**：按「主线/类别」分小节 + 表（改动 | 开关 | 默认 | 说明）。
- 台账是**技术向**的（开关/默认/承载文件/上游吸收状态），与用户视角的 notes 互补——notes 讲体验，台账讲差异。
- 若某改进已被上游吸收，在「上游吸收状态」列注明，避免重复维护。

## 7. 发版前检查清单

- [ ] 基线 = 上一个**发布**的版本（不是上一包）；特性覆盖完整（对照 tasklist 的 done/partial 与 git log）
- [ ] 视角 = 用户；无内部术语堆砌；量化数字有出处
- [ ] 结构七段齐：头部引用块 / 概览 / 主线 / 其他 / 攻略（可选）/ 升级提醒 / 安装
- [ ] 引用了 FORK-vs-upstream.md，且台账已加本版表
- [ ] 文件名与包版本同名；版本号精确到分钟
- [ ] 升级提醒五项逐条过
- [ ] 构建前验证全绿：双模块 build + `TestDesktopRenderTableCoversEveryKey` + `check-fork-integrity.mjs`
