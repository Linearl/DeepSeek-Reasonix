# Reasonix Fork 桌面版 v1.38.3-20261119-2016 — Release Notes

> 基于官方 v1.38.3，包含 **desktop-v1.38.3-20261115-0841** 以来的全部更新（约 9 个时间戳构建、百余项修复与改进）。
> 数据/会话/记忆目录与官方版完全兼容，覆盖安装即可，无需迁移。
> **Fork 与上游差异全览**：见 [FORK-vs-upstream.md](./FORK-vs-upstream.md)。

## 概览

本版集中解决三件事：**此前公告（issue #94）的三类稳定性问题全部修复**——消息响应错位、消息渲染异常、压缩异常，本版逐一收口；**上下文压缩体验整体重做**——长对话压缩时不再丢回合、压完真正瘦下来（压后占用 86.6% → 28.9%）、读数与触发不再自相矛盾；**消息可靠性根治**——回合结束瞬间发的消息、中途插入的引导消息都不再消失。另有启动遮罩首帧即显示、侧栏与跳转条等一批交互修复。

## 🚀 主线一：三类稳定性问题修复（issue #94 收口）

- **消息响应错位**：关闭应用时若有未完成的回合，重启后不再拿着旧快照继续跑——新发的消息一定进入响应上下文；历史链与当轮链的处理差异一并收口。
- **消息渲染异常**：新落盘的消息一定会渲染（补上「新消息必渲染」回归断言）；切走标签页再切回，对方的回复不再空白；重开会话不再卡在「工作中」。
- **压缩异常**：不再出现「没到窗口就自动压缩」的观感——右栏读数与触发判定用同一把尺（全量记录标注），压缩真失败时读数强制重算不抱旧数。

## 🚀 主线二：上下文压缩体验重做

- **压缩不再丢回合**：长对话触发压缩时，回合就地停下等压缩完成并自动继续——不再出现「上下文压缩失败（本轮被放弃）」；就算摘要失败也用现有上下文继续，连续 3 次失败才停止自动重试。
- **压完真正瘦下来**：压缩从「只收外围」改为「保留最近 2 轮逐字、更早的旧轮次收纳」——压后占用 **86.6% → 28.9%**（低于 50% 验收线），压缩频次与缓存失效同源下降。
- **分块不再静默**：任何一次「改用小块摘要」都会在日志和界面说清原因，不再被一次无关失败永久打开。
- **压缩过程看得见**：进度条出现非零速度；完成后悬停「上下文已压缩」卡片可看耗时、平均速度、折叠数、**释放量（如 821.8K → 215.6K）**与摘要命中情况。
- **时序归位**：压缩卡片与进度条出现在回合收尾之后，思考块不再跑到压缩卡片上方。

## 🤝 主线三：消息可靠性

- **回合结束瞬间发的消息不丢**：自动排到下一轮继续执行。
- **中途插入的引导消息不丢**：下一轮模型能看到，对话流有 ↪ 标识与真实时间戳。
- **压缩进行中发的消息不丢**：排队到压缩结束自动注入。
- **切回即显示**：会话间互发的消息切回标签页立即可见，不再需要重开。

## 🧩 其他亮点

- **启动遮罩首帧即显示**：开启实验室「启动遮罩」后，启动第一帧就是遮罩，不再先漏出主界面再盖上（修复开启态下的时序缺陷，不新增开关）。
- **选中即翻译**：对话里选中任何文字（含自己发的）都能翻译/解释/添加到聊天；本版另加「朗读」入口的基础（TTS 即点即读，后续版本开放）。
- **会话目录迁移收口**：历史遗留的旧路径会话全部迁移，旧标签页打开不再报「加载会话历史失败」。
- **effort 切换恢复秒切**：切换「努力程度」不再整屏空白，恢复到早先的即时切换体验。
- **开机更快**：开机不再每次重读全部记忆文件并抢锁——新口径开机热路径 P95 ≈ 1.9s。

## 🔧 其他改进

- 模型列表编辑后即时刷新，已删除的供应商不再残留下拉。
- 右键菜单「新建项目分组」更名为「新建会话组」（中/英/繁三语同步）。
- 跨会话消息深度（hop）超限时的拒绝文案给出真实上限与可执行出路。
- 侧栏展开/折叠时滚动位置保持，不再跳动（贴底态完全稳定，非贴底态行级锚定）。
- 问题跳转条不再被输入框遮挡，末刻度可直达底部。
- 删除会话前校验路径确实在会话仓库内（防路径逃逸，code scanning 三条清零）。
- 「这段对话被谁改掉的」归因线索改为当场落盘，关机崩溃也不丢。
- 更新检查能正确使用系统代理，不再因直连超时静默跳过。
- 实验室新增「智能唤醒空闲会话」开关（默认关）；唤醒开关说明补齐额度影响。
- 大量内部防线与测试加固（跨午夜时间夹具、投影 sidecar 同步、恢复注入排队门等），用户无感但稳定性受益。

## ⚠️ 升级提醒

1. **覆盖安装即可**，数据/会话/记忆目录与旧版完全兼容，无需迁移。
2. **存储模式建议**：推荐并长期停留在 **v3**；v4 可实验开启，但 v3 记录会滞后，存储设置里的迁移可随时把会话迁回 v3（先自动备份）；v5 为上游已弃方向，仅保留导入器。
3. **不要回退到 1.34 / 1.38.1 以下**：事件日志 schema 2 为单向升级，旧构建会拒绝加载（文件本身不损坏）。
4. **已知现象**：大会话切换仍有 1–3 秒加载；首响长尾指标仍在监测收敛中（本版修正了它的统计口径，恒失败假门已消除）。
5. **未验证项**：`-race` 全量竞态检测未执行。
