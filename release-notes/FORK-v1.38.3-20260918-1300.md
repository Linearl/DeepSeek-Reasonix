# Reasonix Fork 桌面版 v1.38.3-20260918-1300 — Release Notes（hotfix）

> **增量基线**：上一包 **`v1.38.3-20260918-2230`**。本包为 host 行为改进包。

## 修复：长任务收尾阶段不再被 host 约束误伤（任务 171）

**症状**：长时间运行的多步任务（如并行开发批次的合并/验证/出包阶段）在收尾时
遭遇 host 约束逐级收紧——命令验证被禁 → 软预算警告（任务被误判为只读调研）→
写操作全面被禁 → 循环守卫误判为死循环并停止重试。用户发一条新消息才恢复。

**根因（恶性循环）**：长任务读多写稀 → 软预算把"本轮无成功写入"误判为
"只读任务" → 被约束拦下的写操作不产生写入凭证 → 误判维持、预算继续收紧 →
agent 降级重试 → 循环守卫把"约束面覆盖了全部合法操作"误判为"同一操作
重复" → 死锁等待用户。

**三项修复**：
1. **循环守卫区分两种情况**：同一操作连续重复（真死循环）仍然拦截重定向；
   连续多轮被**同一约束**拒绝（约束面覆盖）则明确提示"等待用户下一条消息
   即可恢复"并停止重试——不再让 agent 盲目换姿势重试。
2. **被拦的写操作计入非只读信号**：写类工具被守卫拒绝同样打断"只读误判"，
   恶性循环不再成立。
3. **触发前自动落盘交接**：循环守卫触发前把 agent 最近的完整输出写入
   会话目录 `pending-handoff.md`（32KiB 上限，best-effort）——即使会话异常
   结束，交接内容也不丢失。

**验证**：真死循环仍拦（同调用同错误 3 次断言）/ 约束面不误伤（跨工具同
约束不再误拦）/ 边界与双向测试 / agent 全量 177.7s 零失败 + 基线对照零失败。
独立审计五点全 PASS 零必须修复项。

**发布后实锤**：长批次收尾阶段的软预算警告与循环守卫拦截应不再出现。
