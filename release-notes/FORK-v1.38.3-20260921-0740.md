# FORK v1.38.3-20260921-0740

> 基线：`FORK-v1.38.3.md` ｜ 本版仅列相对**上一时间戳包 2256** 的新增
> 类型：**修复 + 观测**

## 修复

**自动化任务「立即执行」在慢启动机器上不再静默失败。**

- 原先等待会话控制器就绪的窗口是**硬编码 10 秒**（40 × 250ms 轮询），而本机实测冷启动需要 **10.23 秒** ⇒ 超时即放弃：**模式不应用、提示词不注入**，用户看到的是"tab 里多出一个会话，但停在询问模式且不工作"。现在改为**等待控制器构建完成的信号**（上限 60 秒），并对超时留下带原因的诊断日志。
- 同一路径上新建的会话**现在会出现在左侧对话列表**。此前当自动化任务声明「项目」作用域、而工作区恰好是应用内置目录时，新建的对话条目会被内置目录过滤规则**整条移除** —— 写进去当场被抹掉，且不留痕迹（这也是"关掉 tab 后彻底找不到"的原因）。

**模型与供应商下拉显示可读名称。**

- 「模型覆盖」下拉此前只显示内部连接名（`deepseek-flash`、`mimo-pro`、`minimax-M3` …），与同名模型混在一起，读起来像"供应商列表里混进了模型名"。
- 现在统一走同一套标签解析：**自定义显示名 > 内置默认名 > 内部名**。内置默认名让常见连接开箱即可读（`deepseek-flash` → `DeepSeek Flash`、`mimo-pro` → `MiMo Pro`、`minimax-M3` → `MiniMax M3` 等），**无需手动配置**。
- **内部连接名与 `<provider>/<model>` 引用完全不变**，既有会话 / 任务 / 标签页状态**无需迁移**；标签只影响显示，永不写回配置。
- 覆盖面：「模型覆盖」下拉、任务配置、设置面板连接列表、模型选择器。

## 诊断观测（为继续定位「首开约 10 秒」）

本包同时带上第二轮观测，用于定位启动期 CPU 饱和（实测峰值 **1824%**，而 `goroutines` 全程无堆积 ⇒ 已**排除**锁等待方向）：

| 观测 | 用途 |
|---|---|
| 会话保存起止 / save-path 锁等待 / 租约释放等待 | 判定"是否在等锁"（切 tab 期间不出现即为反证） |
| CPU 采样拆分 **user / kernel** | 区分"纯计算（解析/GC）"与"IO/系统调用密集" |
| 运行时构建触发者（tab / 触发原因 / 模型 / effort） | 回答"一次启动为什么建 5 个运行时" |
| 首屏载荷（页字节 / 条数 / 尾部重放耗时） | 判定"解码慢"还是"传输慢" |

## 装机验证清单

- [ ] 自动化任务点「立即执行」：会话按任务配置的模式打开，且已注入提示词并开始工作
- [ ] 该会话出现在左侧对话列表，可重新打开
- [ ] 「模型覆盖」下拉显示 `DeepSeek Flash` / `MiMo Pro` / `MiniMax M3` 等可读名；选中后会话记录的模型引用仍为原内部名
- [ ] 其余出现供应商名的地方（设置面板连接列表、模型选择器）与下拉一致
- [ ] 切换几个大会话，观察 `logs/desktop/desktop.log`（诊断用，不影响使用）：

```bash
grep -E "save begin|save end|lock waited|lease release waited" desktop.log   # 是否在等锁
grep -E "runtime build begin" desktop.log                                    # 5 个运行时是谁建的
grep -E "first-paint tail transcript" desktop.log                            # 首屏载荷与尾部重放耗时
```
