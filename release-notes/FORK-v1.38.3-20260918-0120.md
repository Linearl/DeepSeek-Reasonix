### 会话存储四档切换（任务 155）— v3/v4 双写的渐进切换机制

会话存储原来只有布尔开关（legacy / 双写读 v4），现扩为四档，读写端解耦：

1. **仅 v3**（legacy 默认）→ 2. **双写，读 v3**（灰度比对）→ 3. **双写，读 v4**（灰度验证）
   → 4. **仅 v4**（终态，v3 冻结只读）。
- **渐进式跳转校验**：不允许一步跳到 v4_only（必须先经过双写档）；升级最多跨一档；
  降档永远允许；手改配置文件跳档会被启动期 clamp 兜底并告警。
- **自动迁移**：旧配置无损映射（legacy→仅 v3；v4→双写读 v4，保持老用户读端不回退）。
- **档位 4 旧会话兜底**：v3 冻结为只读历史，旧会话可直接打开（只读）。
- **切换遥测**：每次档位切换记录时间/旧档/新档 + 升级前两侧文件数/字节（升级前快照）。
- **重启语义如实提示**：2↔3（纯读端）可热切；跨写端档位需重启，UI 明确提示。
- 设置面板新增四档单选（含每档阶段说明）。

### v4 writer 锁泄漏根治（任务 155 前置健康债）— 切 tab 报错应消失

修复 2130 包日志中 `writer is owned by another runtime` / `operation id conflicts`
两条持续报错（同一条因果链：同步批 op id 冲突 → 条目未登记 → 关闭误判 → 进程内锁
泄漏）。三件套修复：登记即用（失败路径不丢引用）、同进程冲突自愈回收后重试、
同步批 id 带内容摘要（幂等重试）。**装机后这两条 WARN 应不再出现。**

### 停等前自动补证（任务 117 P1）— 实验开关

`[agent] readiness_catch_up`（默认关，次数 1-2 硬上限 2）：交付就绪检查未过时，
自动补证 1-2 轮再决定是否停（走可见宿主消息，非隐藏重试）；补证成功会撤回
"等待用户"恢复卡片。默认关闭时行为与上游逐字一致。

### 派遣经济学（任务 118 剩余）— 实测驱动的三个改进

- 实测修正：50 次派遣扫描显示 writer 类派遣 89.5% 已后台化，**真瓶颈是只读调研
  从未有过后台选项**（12/12 全前台）；写并发上限 3 从未被触及（有效并行度=1 的
  根因是写路径声明率 0%）。
- `[agent] read_only_task_background`（默认关）：开启后只读调研子任务出现后台选项。
- `[agent] plan_research_gate`（默认关，1-2 轮）：计划模式下若本回合未派只读调研，
  先注入一轮提示要求调研或说明未看区域。
- 子代理默认步数文案与实现对齐（two-thirds / 最低 12，此前两处文档写旧值）。
