## 🔧 Fork 修复

### 历史加载 reload fallback（#9468，本版重新应用）

上滑加载更早历史时，若后端已重写会话（快照恢复路径），上游的身份检查会误拒 reload 结果，导致"earlier conversation could not be loaded"且重试无效。本版恢复 v1.31.4 的修复顺序：reload 结果优先于 fingerprint 拒绝执行。该修复曾在 v1.32 合并时被上游同名区域改动覆盖。

### kill_shell 无法终止持锁后台子代理（上游 #9564）

`kill_shell` 被误分类为 workspace writer，后台写子代理持有 write path 锁期间，主对话用它终止该子代理会被同一把锁拦截（"write path is claimed by a running background subagent"），持锁子代理无法被杀。本版将 `kill_shell` 与 `wait`/`bash_output` 同列为非变更工具，从写锁协调中移除——终止操作不再需要锁。

### MiMo 截断响应污染历史导致 HTTP 400（上游 #9566）

MiMo 输出上限（128K）低于 DeepSeek（384K），长输出 turn 被服务端截断（finish_reason=length）时，流式中途拼接的 tool_call arguments 是非法 JSON 片段，被原样写入会话历史；下一轮请求回传后 MiMo 严格校验拒绝整个请求体（400 Invalid request parameters），点"继续"必复发，只能换模型逃生。本版在 assistant 消息入历史前做 repair：非法 JSON 的 arguments 修为 `{}`，请求体保持合法——工具以正常参数缺失错误收尾，模型可重试。

### 会话面板改名后左侧项目树不同步 / 标题闪回（上游 #8280 残留）

桌面端有两套会话标题存储：会话面板改名只写 Session 级（branch-meta CustomTitle），左侧项目树的权威标签读 Topic 级 titles 文件——改名后左侧长期显示旧自动名，且 catalog 状态翻转时短暂显示新名又闪回旧名。本版在改名链路上把手动标题投影到 Topic 级存储并更新已打开的 tab，两个改名入口收敛为同一个可见名字。

### 项目分组在 classic/creation 布局不可见（#9222 完善）+ 样式恢复

项目分组（A 套）的列表渲染此前只在 workbench 布局实现——classic/creation 用户能建组、能移入项目，但左侧列表完全看不到分组结构；且 1.32 合并时分组 CSS 被 auto-merge 静默丢弃（caret/图标/计数/操作按钮/移动分组面板共 194 行）。本版：① classic/creation 布局在有分组时渲染与 workbench 相同的分组结构（无分组时保持原纯平铺，零行为变化）；② 空分组也渲染标题行（创建后立即有视觉确认）；③ 恢复全部丢失的分组样式并适配 1.33 主题 token。

以下为本版 tag 重构建追加的六项（对应 2026-08-29 整改批，同一版本号 `desktop-v1.33.0+fork` 内交付）：

### 折叠分组会话计数偏小（上游 #9518）

项目内会话分组（B 套）的计数徽标此前基于当前渲染列表求交集——classic 视图 5 条预览截断、workbench 50 条分页都会让折叠状态下的计数偏小（折叠时计数是唯一信息源，最刺眼）。本版改为后端权威：`GetProjectGroups`/`ListProjectGroups` 返回前按 session catalog 剔除已不存在的会话 id（catalog 未就绪时降级不过滤），前端计数直接读持久化成员清单。已删除会话的残留 id 天然被剔除，两层截断误差同时消失。

### 子代理任务进度 TPS 心跳（上游 #9521）

`task` 子代理长时间推理（30-60 秒无新预览）时，"activity Xs ago" 无法区分「慢慢推理」与「挂死」。本版在进度管线按 3 秒滚动窗口统计子代理流式输出速率（bytes/4 估算），随 status 事件携带；任务卡 chip 在产出进行中显示 `~N tok/s`（工具执行期无流式输出不显示，避免误读为卡死）。限频：每子代理每秒至多一次、速率变化 ≥2 tok/s 才发，共享既有 32 ev/s 组预算。

### 运行中子代理可观测（上游 #9522 Phase 1）

后台 task 此前是黑盒：job 只显示 `running`，运行中连"子代理在做什么"都读不到。本版：① 后台 task 的推理/回复/通知增量实时流入 job 输出缓冲（带通道分节标记）——`wait`/`bash_output` 运行中即可见子代理动态，产物日志同步留存；② 完成通知附带 400 字符内的结果摘要（UTF-8 安全截断），主对话多数情况无需再花一轮 `wait` 收集。Phase 2（`task_id` 运行中追加指引）后续版本交付。

### 会话切换模型接管后界面错排（上游 #9567 关联）

跨模型接管会话时，transcript 因 surface 边界整体 remount，但 remount 后没有强制钉底——视口停在旧位置，最新 turn 被顶出视口下方。本版在 incoming surface 首次绘制提交后重新断言 tail-follow 钉尾并滚动到底部；用户随后的主动滚动仍可自由离开。

### 切回会话/停在历史位置时历史回答 Markdown 不渲染（上游 #9570）

历史行走异步 worker 解析 Markdown，解析完成后无条件依赖"当前处于底部"（2px 阈值）决定是否渲染——只要不在底部就保持明文，需滚动到底才触发。本版把延迟提交限制在真正需要的场景：长回答（超过一个尾部窗口）且正在视口内阅读时保持稳定回退（避免明文→尾部窗口切换导致内容消失与滚动跳变）；短回答（全文不超过尾部窗口，切换不删任何块）与视口外的行在解析完成后立即渲染。

### 共享窗口模型上下文超限死亡螺旋（上游 #9572）

glm-5.x 等 1M 共享窗口模型上，投影失效（切模型）后可见视图退回全量历史，pressure 触发的摘要请求以无上限的 fold 全量直接发出（实测 994,833 tokens），超过共享窗口必然 `1261 Prompt exceeds max length`，重试只推进 generation、永远装不上折叠投影，会话不可恢复。本版：① 所有自动压缩路径（含 pressure）统一套用摘要输入安全前缀（`maximumSafeSummaryPrefixEnd`，共享窗口预留输出预算）；② 窗口模式未知且从未成功过请求的网关（新切换的 provider 形态）回退按配置窗口裁剪，不再跳过安全上限；③ 无安全折叠区且非 mustFree 时软跳过本次折叠而非发出必然被拒的请求。手动 `/compact` 保持不裁剪。

以下为同版本号第二次重构建追加的五项（2026-08-29 第二批整改）：

### remote/serve 会话 Markdown 缓存永不命中（上游 #9573）

历史行 id 有两套生成体系：本地会话 `he:<entryId>`（缓存能命中）、remote/serve 水合 `h<seq>`（每次加载的序号，缓存永不命中）——remote 会话每次切回必现明文、重新 worker 解析。本版让无持久 entry id 的行以内容哈希派生缓存键（revision 本身即 FNV-1a 指纹，存储侧 source 比对兜底碰撞），写入与读取两侧统一，remote 会话切回即命中缓存，且与 #9570 的门控解耦。

### 每 turn 暴露上下文预算 + 系统提示文档化压缩机制（上游 #9520）

模型此前既看不到上下文用量、也不知道压缩机制存在，长任务容易在窗口将满时被仓促收尾或放弃。本版：① 系统提示追加静态压缩契约说明（「旧 turn 会被摘要而非丢失，按波次规划大任务」——静态文案不破坏前缀缓存）；② 每轮 user turn 头部注入 `<context-budget>` 一行（`41k/128k tokens (32%); auto-compaction at 80%`），数字与 ContextManager 实际比较阈值同源；达触发线 85% 时文案升级为「接近自动压缩——旧上下文会被摘要而非丢失，按波次规划剩余工作」。动态数字放在前缀末端而非 system prompt，刷新只扩展缓存前缀、不使其失效。

### task 工具后台模式决策引导（上游 #9526）

后台执行机制（run_in_background/fleet/parallel_tasks）早已完备，但工具描述从未提及执行模式——一个 turn 内 N 个独立子任务会阻塞在第一个前台派发上，其余永远派不出去。本版按 opencode 成熟形态补三层提示词引导（零逻辑改动）：① 工具描述尾部加决策规则（默认前台、需要结果才前台；独立任务用后台并行派出）；② 后台派发返回文案加行为指令（「不要 sleep/轮询——做不重叠的工作或告知用户后结束回合」），完成通知自动兜底。

### 后台子代理 task_id 追加指引（上游 #9522 Phase 2）

派出的后台子代理一旦跑偏只能杀掉重来。本版 `task` 工具新增 `task_id` 参数（即 `run_in_background` 返回的 job id）：**运行中**——prompt 作为追加指引注入子代理（复用主对话同款 steer 门控，在其下一 turn 边界消费，已完成的工作与上下文全部保值）；**已结束**——transcript 以该指引续跑并直接返回续跑结果；**排队中**——明确报错提示稍后再发。加上 Phase 1 的可观测能力（预览流入 job buffer + 完成摘要），后台子代理从「发射后不管」变为「可观察、可干预、可续派」。

### 标准模式混合命令修复确认（上游 #9471，随 1.31.4 已交付）

标准（非交付）回合对「变更+验证」混合 bash 命令（如 `go build ./... ; go test ./...`）的 shape 拦截已于 1.31.4 移除（对齐 Codex：bash 的 `&&`/`;`/`|` 语义对模型透明，拆段只增加往返）；交付（closed-loop）模式保留严格拦截以保护验证 receipt。本次随跟踪整理确认状态并在上游 issue 关联评论。

### 项目分组展开状态持久化（#9222 跟进）

项目下对话分组的展开/折叠状态此前只存前端内存，应用重启或项目栏重挂载后全部分组自动重新展开——对话多时单个展开分组占据几乎整个项目栏。本版将折叠状态持久化到 localStorage（与分组归属持久化对称）：重启/重挂载恢复此前状态，仅折叠 id 被记录（新建分组默认展开），删除分组时同步清理残留标记。

## 🆕 第二轮交付（2026-08-29 晚）

### 会话输入框草稿跨重启持久化（上游 #9580）

切换对话立即保存输入框草稿；不切换直接关闭应用时经 pagehide 强制落盘（防抖 150ms，丢失窗口趋近于零）。持久化内容覆盖纯文本之外的完整可恢复状态：**粘贴的长文本块**（标签+内容，nextPasteId 重建，不再出现悬空占位符）、**图片/文件附件**（路径+显示名，预览 URL 按需重生成）、附件去重键与 @ 引用。单草稿 256KB 上限，超限/清空自动清理条目。

### 项目颜色筛选按钮失效修复（#9221 样式恢复）

上游合并时 auto-merge 静默丢弃了颜色筛选功能的 42 行配套 CSS（无冲突标记、无构建报错），菜单渲染到无定位锚点处被侧栏裁剪——按钮点击"毫无反应"。本版恢复全部样式并完成主题 token 迁移（`--fg-faint` 替代已退役的 `--fg-muted`、swatch 边框主题化），同时补齐筛选按钮基础样式。配套引入 **fork 完整性核对脚本**（`scripts/check-fork-integrity.mjs`，37 项 fork-only 标记 grep，合并上游后必跑）杜绝同类事故。

### heartbeat 任务按任务覆盖模型（上游 #9070）

定时任务编辑器新增 Provider / Model 覆盖输入（留空保持会话默认），执行时按任务切换模型；任务 JSON 同步支持 `provider`/`model` 字段。不同任务可分别指定轻量/重模型。

### 后台写子代理不再冻结主对话工具（上游 #9592）

后台 writer 子代理存活期间，主对话的只读与管理类工具（read_file / wait / kill_shell / task 等）不再被写协调误拦——修复前主对话除等待外全部不可用直到子代理结束。Hook 作者可在配置声明 `mutatesWorkspace: false` 进一步豁免变异类 hook。实测验证：writer 运行中 read_file/wait 正常、writer 结束后全部即时恢复。

### 手动 /compact、/new 等命令误报「发送失败」修复

手动输入 `/compact` 回车时前端报 "Send failed: turn admission did not produce a durable turn id"，实际压缩照常执行——slash 会话操作不产生 turn，admission 回执被误判为发送失败。本版将「submit 已受理但不产生 turn」改为正常受理回执（空 turnId），`/new`、`/clear`、`/model` 等全部命令同样受益；从命令列表选择提交的路径本就正常。

### 运行中 live 分区尾部预算（上游 #9579）

运行中 turn 的 live 分区此前把用户消息之后的所有行全部卷入（Footer 区域），工具未折叠时几十行内容紧贴用户消息、挤占整个视口。本版 live 分区只保留最近 5 行（含流式内容与排队消息），更早的已完成行回归对话流自然堆叠——与 turn 结束后的落位完全一致；折叠场景渲染紧凑头部，行为不变。

### 超长会话一键提取要点到新会话（上游 #9082，fork 率先落地）

超长/无法续聊的旧会话（如压缩死锁、投影失效、超窗）提供 `/extract` 命令：离线、分块、结构化地读取整个会话——按指数衰减分段（最新 64KB 保留最精细细节 → 128K → 256K → 512K → 更早 768KB 粗折叠，相邻段 16KB overlap 防边界丢信息，分段不切断单条消息），每段独立摘要后合并为一份标准 `compaction-summary`（Standing facts / Goal / Decisions / Files / Commands / Errors / Pending），自动创建新会话并注入要点作为接续起点。与 `/compact` 的单次摘要（丢早期内容）互补，是对超窗会话的**全量无损要点恢复**。
