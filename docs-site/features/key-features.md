# 关键特性详介

[全部特性一览表](feature-index.html) 收录了 81 项实验特性的完整索引；本页按 **效率提升 / 易用性 / 稳定性 / 性能优化** 四大方面，挑出最值得先知道的能力展开讲。编号与一览表一致，可交叉查阅。

## 效率提升（自动化）

### 跨会话协作 <span class="fnum">102</span> <span class="badge badge-stable">已转正</span>

多个会话之间可以互相发消息、收消息、等待回执，形成真正的多 agent 协作。左下角邮箱图标进入**信件中心**，跨会话消息集中查看与管理。

- **忙时不丢消息**：写入一次完成，忙时自动排队，投递前查重（短时间内重发完全相同的内容会被合并为一条）。
- **空闲自动开工**：空闲会话收到消息约 30 秒内自动开工，此前可能永远沉默。
- **回执分级**：无需行动的回执静默进返回值与通知，需行动的才注入会话——省掉大量无意义的回复轮次。

**为什么这么做**：消息投递的可靠性是多 agent 协作的地基。丢失、重复、静默不唤醒这三类问题任何一类复发，整条协作链就不可信。

### 自动驾驶 <span class="fnum">101</span> <span class="badge badge-stable">已转正</span>

让 agent 长时间自主运行，同时保持可控。配合分级审批姿态（Ask / Auto / YOLO，`Ctrl+Y` 切换）与 Plan 先规划后执行。

- **ask 面板**显示剩余秒数与「接管」按钮——人在思考时可以离开鼠标，超时自动代答。
- **决策链显式化**：审批、ask、终止、引导四条链路各有明确的定义，不靠隐式约定。

**为什么这么做**：无人值守的前提是「出事时人能随时接管」，而不是「祈祷它不出事」。

### 快捷指令 <span class="fnum">311</span> <span class="badge badge-recommended">推荐</span>

把高频操作固化成文本片段：在输入框开头敲 `!!` 唤起快捷指令列表点选插入；也可从输入框「+」菜单进入。少打字、少描述、少出错。

### 会话图墙 <span class="fnum">419</span> <span class="badge badge-recommended">推荐</span>

一屏网格总览全部会话。**入口：命令面板（`Ctrl+K`）**——这是唯一入口。适合同时挂着十几个会话的场景——不用在侧栏里滚着找。

## 易用性（操作方便，快捷功能）

### 右侧边栏增强

右边栏承载文件面板、工作区预览等辅助面板，与主对话并行不抢位；支持[悬停展开](feature-index.html)（<span class="fnum">407</span> 可选），鼠标扫过即展开、移开即收起，常驻不占宽度。**信件中心在左侧「协作中心」**（点左侧边栏的协作入口进入）；**批量会话操作从项目区头部的管理图标进入**（归档/移动一键完成）。

### 输入框功能增强

输入框是使用频率最高的控件，fork 围绕它做了一组增强（**入口都在输入框下方工具行**：`+` 附加、`^` 折叠切换、截图、历史、命令面板图标）：

- **`/` 命令 · `@` 文件 · `!` 终端**：三种前缀分别唤起命令列表、文件引用与终端直通，不用离开键盘。
- **`!!` 快捷指令**：在输入框开头敲 `!!` 唤起快捷指令（常用文本片段）列表，点选插入。
- **草稿持久化**（<span class="fnum">426</span> 可选）：切会话/重启后未发送的输入不丢。
- **改写**：选中已有内容快速润色重写，不必剪切到外部工具。
- **截图**：直接粘贴或拖入截图即可作为上下文，视觉问题当场问。
- **模式下拉定宽**：审批姿态切换（ask/auto/yolo/autopilot）开合零跳变，不挤动布局。

### 过程折叠与展开

思考过程与工具调用默认折叠为一行摘要；**输入框工具行的折叠按钮（^）可临时切换全局折叠/展开**，不必进设置改偏好。思考过程做了**流式呈现**（参考 DeepSeek anchored 插件的实践）：生成中实时可见思路，不必等答完才展开——平衡节约空间与信息透明，长会话读起来干净，排查时又能一层层展开溯源。

### 快捷打开文件与路径

对话里出现的文件路径可直接点击跳转文件面板；命令面板（`Ctrl+K` 或顶部搜索图标）可快速搜索并打开任意会话与面板——**建议熟练使用 `Ctrl+K`**，它是全应用最快的导航入口。

### 视图布局 <span class="fnum">412</span> <span class="badge badge-recommended">推荐</span>

分栏、轨迹视图、左右边栏悬停展开、表格按栏宽换行、发送目标选择器等一组界面能力，默认关闭时布局与引入前完全一致。

**为什么这么做**：界面改动最容易打破既有肌肉记忆。全部挂实验开关，让你自己决定哪些值得开启。

## 稳定性（不容易异常崩溃）

### 存储版本与数据安全 <span class="fnum">702</span> <span class="badge badge-unstable">未稳定</span>

fork 的存储策略是 **v3 为长期推荐档**；v4 可用但 v3 侧记录会滞后；v5 是上游新引入的方向，稳定性未经我们验证。提供 v4→v3 迁移器（带备份提醒与进度可视化）。

**注意**：不要回退到 1.34 / 1.38.1 以下——会话事件日志的 schema 是单向升级，旧构建会拒绝加载（文件本身没有损坏）。

### 投递与会话生命周期治理

历史上两类高频异常——**跨会话消息偶发丢失/重复投递**与**会话「假运行」**（异常退出后卡在运行态、新消息被吞）——已在一轮专项中根治（正式 Release `20261012-0045` 起包含）。此后持续收口：写入一次完成、忙时排队、空闲自动开工、终态收敛，让「发了没反应」「卡在运行中」不再发生。

## 性能优化（资源占用减少，速度提升）

### 乐观并行写入 <span class="fnum">301</span> <span class="badge badge-recommended">推荐</span>

多个会话写同一个项目不再整工作区一把锁串行：write-if-unchanged 检测陈旧内容并拒绝错误写入，默认串行保证安全，可在设置里关闭。

**为什么这么做**：一把锁简单但吞吐极低；完全无锁则会写坏数据。折中点是「默认安全、显式提速」。

### 冷会话归档（zstd） <span class="fnum">705</span> <span class="badge badge-optional">可选</span>

冷会话的主转录整文件压缩为 `.jsonl.zst`，冷读透明解压，恢复活跃时物化回明文。热会话保持明文，不受影响。开关关时会话文件与引入前逐字节一致。

**为什么这么做**：长期挂着几十个会话时，冷数据占的磁盘远超必要。压缩冷的、不碰热的，是收益/风险比最好的一刀。

### 内存与切换速度治理

桌面版内存基线从 2~4GB 降到 **700~800MB**（v4 快照 payload 有界化 + transcript 几何哈希缓存）；大会话切换从 71.7 秒降到 **3 秒级别**，切模型/档位从 10 秒以上降到 3 秒级别。治理过程与实测数据见[更新日志](changelog.html)各版本条目。
