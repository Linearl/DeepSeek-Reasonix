# Block 审计计划模板（block-audit-plan）

> 用途：单轮开发计划的「3-b Block 级审计安排」节——多 Block 批次规划时，为每个 Block 预写审计框架（2026-09-22 从批三实战提取；实际子对话派发由审计主会话在 Block 合并后执行，模板细节见 ll-iteration-dev/templates/audit-split.md）。

## 背景要点（写计划时对照）

- **Block 间闸门必须含审计**：合并 → 测试 → **审计** → 通过才进下一 Block（批三教训：审计攒到批次末尾做 + 抽查式 = 220 剥除缺口/202 跨 root 不成立这类问题漏网）。
- **审计主会话自行派子对话**：管理会话只定框架（谁审、预计几个子对话、覆盖要求），不预切分任务——分工由审计主会话自己定（更公平）。
- **全量纪律**：逐任务全量代码审读 + 验收锚点逐条核对，汇总附覆盖声明。

## 每 Block 一节（示例骨架）

### Block N 审计安排

- **审计对象**：Block N 合并后的 main-v2-stable 区间 `<上一门 sha>` → `<本门 sha>`
- **审计主会话**：<新建（reasonix 分组）/ 复用 <contact_id>>
- **子对话计划**：预计 N 个，按域切（<域 1> / <域 2> / <域 3>）——实际分工由审计主会话定
- **全量覆盖要求**：Block N 全部任务逐行审读 + 验收锚点逐条核对；汇总回信附「任务→子对话」覆盖声明
- **特别核对点**（来自本 Block 已知交叠）：<例：任务 A 门控 × 任务 B 工具注册面一致性>
- **通过标准**：blocker/major 全清零（修复+复验）才进 Block N+1

## 批次收尾审计

最后一个 Block 通过后，是否还需要批次级收尾审计：**否**——各 Block 已审计，批次末只做「出包前测试文档」（改动点清单+验证方法，见 parallel-dev §5.7.0）与台账。
