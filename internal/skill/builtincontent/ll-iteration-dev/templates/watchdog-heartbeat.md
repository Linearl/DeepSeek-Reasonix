# 心跳守护模板（parallel-dev-watchdog）

## 心跳任务注册（批次开工时创建，收尾时删除）

写入 `%APPDATA%\reasonix\heartbeat-tasks.json` 的 `tasks[]`（用 read→改→write 原子更新，勿并发改写）：

```json
{
  "id": "parallel-dev-watchdog-<批次号>",
  "title": "守护-<批次号> 并行开发心跳",
  "prompt": "你是并行开发批次 <批次号> 的守护心跳。只做三件事：①读 <批次状态文件路径> 与各线状态文件；②用 get_session_status/通讯录查主对话（contact_id=<主会话id>）与子对话活跃度；③按下方判据决定是否发唤醒。禁止写代码、禁止改任务、禁止跑测试。若批次清单不存在或全部完结：用 heartbeat 任务删除接口移除本任务 id（自愈清理，不依赖主对话），然后结束。",
  "interval": "20",
  "enabled": true,
  "newConversationEachRun": true,
  "approvalMode": "yolo"
}
```

## 判停与唤醒判据（心跳会话内执行）

1. **先查再唤**：主对话 `state=running` → 不打扰，直接结束本轮；
2. **宽口径**：主对话 lastActivity 距今 **> 40 分钟**（2×周期）才判停——长思考/长工具会误判；
3. **去重**：主对话 inbox 已有未消费的本批次唤醒 → 不再发（防 20min×N 堆积）；
4. **备案免报**：状态文件/台账中已备案「空闲原因」的子对话（交付完待命/等待外部输入）不报停滞——只报**未备案**的 >2h+inbox0 线（20260930 教训：三连误报已备案线浪费主对话注意力）；
4. **唤醒消息必带自证上下文**（主对话可能已被压缩/重启）：

```
【守护唤醒·批次 <批次号>】你已静默 >40min，按心跳约定唤醒。
进度指针：<批次状态文件路径>；线程 hash 链：<最后已知 msg_id>；你最后处理到：<状态文件最后一条摘要>。
请：查状态文件对齐进度 → **用 get_session_status 检查全部在飞子对话工作状态**（重点三类：①交付未收=子对话出了新件但主对话未收回信→read_session_tail 补审；②idle+inbox0=疑似漏收交付→read_session_tail 确认后补审；③unknown+lastActivity>1h=read_session_tail 定停摆原因，必要时改派）→ 决定继续推进或调整派活。已在台账/状态文件备案「空闲原因」的线免报。
（本消息为守护心跳自动发送，唤醒去重 id=<batch>-<date>）
```

## 生命周期铁律

- **自愈清理优先**：心跳每次自检批次状态，完结/不存在 → 自删任务；主对话收尾删除只是兜底（防中断遗留僵尸心跳——9614 族教训）；
- **单守护多批次**：多个批次并行时共用一个心跳任务，prompt 读「批次清单文件」逐批检查，不每批次建任务；
- **任务 id 规范**：`parallel-dev-watchdog-<批次号>`（多批次共用时用 `parallel-dev-watchdog-<root>`），登记进批次状态文件；
- **心跳禁干活**：只查+唤+自删，任何写代码/派活/改文件都违规（可用 §4c 脚本扫心跳会话验证：变更类应为 0）。

## 高级定时器迁移契约（未来）

定时 sleep+可被提前唤醒的高级定时器落地后：**只换触发源**（会话内 scheduler 自唤醒，不再建 heartbeat 任务、不产生额外会话），「唤醒消息带状态指针 + 自愈清理 + 宽口径判停」契约**原样保留**。注意 eventtrigger 一族有 interval 下限（`below min must be refused`），迁移时核对最小周期。
