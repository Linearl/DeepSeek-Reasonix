# 大坑详版（PITFALLS）· B4 外移

> `SKILL.md` §6 只保留一行版触发器；**现象 / 根因 / 逃生步骤**的完整版在此。
> 命中某条的**一句话版**后，来这里查细节。

---

### 1. `rm -rf` 会跟随 Windows junction 删掉目标内容

- **现象**：清理 worktree 时把**主仓的 `node_modules` 一起删了**（首轮实战事故）。
- **根因**：Windows junction（`mklink /J`）对 `rm -rf` 不构成边界，递归删除会穿透链接删到真实目标。
- **逃生**：
  ```bash
  cmd //c rmdir <junction>          # 只删链接本身
  # ⚠️ 必须验证删除成功，绝不 2>/dev/null 吞错
  ```
  顺序永远是：**先删 junction → 再 `git worktree remove --force` → 再 `git branch -D`**。

### 2. junction 删除失败会被 `git worktree remove` 拒绝

- **现象**：报 `Directory not empty`。
- **原因**：junction 还在，worktree 目录非空。
- **逃生**：先按第 1 条清 junction，**并验证**，再 remove。

### 3. new Desktop keys 必须带 render.go 渲染行

- **现象**：新配置键保存后**被静默丢弃**，无任何报错。
- **根因**：渲染表是保存链路的白名单；表里没有 = 直接丢。
- **防线**：`TestDesktopRenderTableCoversEveryKey` 是**唯一防线**——构建前必须绿。
- **逃生**：新增 key 时同步加 `render.go` 渲染行（见第 4 条全链路）。

### 4. 新实验开关走全链路七件套

```
config → setter → 渲染表 → UI → bridge → types → locales
```
- **漏一环 = 保存丢**（不是报错，是静默失效——最难查的一类）。
- **逃生**：加开关时把这七项当清单逐项打勾。

### 5. boot 快照 vs 调用时求值（S4 约定）

- **规则**：collab 类工具的**会话路径 / 身份一律调用时求值**，不要 boot 快照。
- **根因**：boot 时求值会把启动那一刻的状态固化，会话重建/迁移后就是错的。
- **逃生**：写这类工具时先问「这个值在会话生命周期内会变吗？」——会变就不能快照。

### 6. 前端测试用 `npx tsx <file>` 直跑，绝不用 vitest 路由

- **现象**：vitest 报 `No test suite found`。
- **关键**：这**是正常现象，不是环境损坏**——前端 harness 是自建的，vitest 路由不适用。
- **逃生**：不要为了"修好 vitest"去改配置，直接 `npx tsx <file>`。

### 7. heredoc 写含反引号的 markdown 会被命令替换

- **现象**：写文件时反引号内容被 shell 执行/替换，文件内容损坏。
- **逃生**：markdown 一律用 `write_file` / `edit_file`，不要用 `cat <<EOF`。
- **关联**：第 12 条（中文文件禁 PowerShell `Set-Content`）。

### 8. 主会话派活消息必须带收信地址（contact_id）

- **现象**：子会话**回不了信**，只能等管理会话主动拉状态文件。
- **逃生**：派活消息里显式写「我的 contact_id：xxx（回信有址）」。

### 9. worktree 里跑构建可能报命令找不到

- **现象**：`command not found` / 依赖缺失。
- **根因**：junction 未建好或依赖不完整。
- **逃生**：**先确认 junction / 依赖完整，再归因代码**——否则会去改没坏的代码。
- **关联**：junction 是**借主仓的依赖，不是自己的**；派活消息要写明「pnpm 结构若报缺依赖就用主仓跑」。

### 10. 并行会话写同一 tasklist 文件会冲突

- **逃生**：**tasklist 只由主会话统一更新**——写进派活禁项。

### 11. 跨会话回信 thread_id 必须用「自己收到的入向消息 id」

- **现象**：用自己发出的 id 会**链路校验失败**。
- **送达判定**：看对方 `inbox.jsonl` + `seen.json`；**`queued` ≠ 已读**。

### 12. 对大文件做 edit 前必须一次完整 read

- **现象**：连续「编辑失败」——**批五线 C 实证：删 2 行注释连报十几次**。
- **根因**：`range` 分段读的**累计覆盖不被承认**。
- **重要性质**：**失败即零写入、不留半截**——可用 `git diff --stat` 核实文件未损坏。
- **逃生**：`$MIMO_PYTHON -c` 行级改写。
- **⚠️ 中文文件禁 PowerShell `Set-Content`**（会写坏 UTF-8）。
- **已撤回的旧说法**：原写「`intent=full` 单次约 31KB」**无代码常量、无历史报错支撑**（reasonix 代码 grep 不到此类常量，会话历史 0 命中）——不要再用这个数字做判断依据。

### 13. 对应用会写回的配置文件打补丁，幂等判定必须段级

- **现象**：补丁重复施加 / 判定失效。
- **根因**：应用渲染会**重排字段位置 + 加对齐/注释**，只查「name 行下一行」必然失效。
- **实证**：2026-09-21 provider hidden 实战。
- **逃生**：幂等判定按**段**（一段完整结构）而不是按相邻行。

### 14. 批次交付/出包须出验证清单（通用，2026-09-23 用户定）

- **要求**：落盘清单文档，两类**分列**：
  - **🤖 已自验**：构建 / 测试 / 产物级校验
  - **👤 待人工**：装机 / 目视 / 场景复现
- **闭环规则**：装机验证结果回填清单，**人工项通过后任务才转 `verified`**（装机实测前不得转）。
- **位置**：`tasks/<批次>-装机验证清单-*.md`
- **v3 增补**：清单必须含**「已知未含项」**——即 §5.8 被踢出范围的线，逐条列出。
