# 派活消息骨架（DISPATCH MESSAGE）

> 管理会话派活时按本骨架组装。**顺序不要改**——身份卡在前，任务在后，这样子会话读到的第一件事是"我是谁、哪些规则不适用于我"。

---

## 骨架

```markdown
【身份卡】
<整段粘贴 templates/role-dev.md | role-audit.md | role-merge.md>

【任务】
任务号：240
标题：给 Desktop 新增 theme.accent 配置键
工作区：<worktree 绝对路径>        分支：wt-240        基线 commit：<sha>
任务正文：<tasklist 文件路径>:<行号>
范围：<明确列出要改/不要改的边界>

【验收标准】（逐条可证伪，直接引用阶段 2 计划原文）
- [ ] 保存后重启仍生效
- [ ] TestDesktopRenderTableCoversEveryKey 绿
- [ ] ...

【本批共享产物与约定】（v3 · 见 §5.1）
- 命名方案：<本批新增的键名/标记/命名约定，所有相关线都必须遵守>
- 接口契约：<渲染表 / 七件套链路 / 跨模块签名>

【禁项】
- 不 push
- 不出包
- 不动 tasklist（tasklist 只由管理会话统一更新）
- <其它>

【回报格式】
按 templates/report-schema.md 四字段，正文 ≤30 行，超出写文件给路径。
③「验了什么」必填。

【回信通道】
- 里程碑 / 阻塞：steer 即时回信
- 普通进展 / 细节：写状态文件 tasks/<批次>-进展-<线>.md
- 我的 contact_id：<contact_id>（回信有址）

【状态文件义务】
开工写一行 → 有意义进展写一行 → 需拍板的事写进「需要管理决策」列
进入审计修复循环后，每轮更新「轮次」列（已用/5）
```

## 检查清单（发出去之前逐条对）

- [ ] 身份卡粘了**全文**，不是"你是开发会话"一句话
- [ ] worktree **绝对路径** + 分支 + 基线 commit 三者齐全
- [ ] 任务正文给了**文件 + 行号**（不是"看 tasklist 里那个"）
- [ ] 验收标准**逐条可证伪**（"体验流畅"不算）
- [ ] 本批**命名方案 / 接口契约**写了（只给相关线是不够的，要给**所有**相关线）
- [ ] 禁项列全（尤其"不动 tasklist"）
- [ ] 回报格式与上限写了
- [ ] **回信通道明确写了**（不让子会话猜）
- [ ] **contact_id 给了**（否则对方回不了信——§6.8）

## 常见错误

| 错误 | 后果 |
|---|---|
| 不附身份卡，让子会话自己推断角色 | 它可能把管理会话的铁律套到自己头上（拒绝写代码 / 拒绝派子对话） |
| 没给 contact_id | 对方回不了信，只能等你主动拉 |
| 没写回信通道 | 阻塞消息走 followup，积压到你 turn 结束才看到 |
| 验收标准含糊 | §5.6 审计无锚点可对，只能"整体看起来没问题" |
| 派活消息里没写禁项 | 子会话顺手 push / 改 tasklist，与并行线冲突 |
