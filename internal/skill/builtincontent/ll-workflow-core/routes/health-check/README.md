# Health-Check 路由

本目录包含 health-check 子工作流的资源文件，原为独立技能 `ll-health-check`，现已整合到 ll-workflow-core 中。

## 工作流概述

**用途**：项目健康检查与战略指导，识别不足、规划下一步、提取可复用的方法论。

**核心能力**：
- 五维健康评估（架构、安全、测试、债务、流程）
- 七种债务模式识别
- 版本生命周期判断
- 可复用方法论提取

**简称**：`hchk`

**触发条件**：
- 用户提到健康检查、版本启动检查、版本复盘、战略校准

## 目录结构

```
routes/health-check/
```

## 工作流阶段

| 阶段 | 名称 | 说明 |
|------|------|------|
| A | 项目快照采集 | 采集项目当前状态的客观数据 |
| B | 五维健康评估 | 从架构、安全、测试、债务、流程五个维度评估 |
| C | 模式识别与方法论提取 | 识别反复出现的债务模式，提取可复用的方法论 |
| D | 诊断与建议生成 | 基于快照和评估结果，生成具体的诊断报告和行动建议 |
| E | 经验沉淀（可选） | 将新发现的模式或教训沉淀到项目经验库 |

## 五维健康评估

| 维度 | 权重 | 评估要点 |
|------|------|---------|
| 架构健康 | 20% | 分层清晰度、组件职责、API 一致性、循环依赖 |
| 安全健康 | 20% | 认证默认、输入校验、CSP 配置、凭据管理 |
| 测试健康 | 20% | 单元覆盖率、集成测试、E2E 测试、CI 集成 |
| 债务健康 | 20% | TypeScript strict、any 使用、大文件、重复代码 |
| 流程健康 | 20% | 版本规划、任务规范、审计机制、文档同步 |

## 七种债务模式

1. **快速原型债务**：原型阶段的临时方案未清理
2. **不彻底的模块化**：模块边界模糊，职责不清
3. **响应格式漂移**：API 响应格式不统一
4. **样式债务累积**：CSS/样式问题累积
5. **审计驱动的打地鼠**：审计后修复，但未根治
6. **安全后置的代价**：安全问题后期修复成本高
7. **范围蔓延的温水煮青蛙**：需求不断膨胀

## 版本生命周期阶段

| 阶段 | 版本范围 | 特征 |
|------|---------|------|
| 原型验证 | v01-02 | 快速验证核心功能 |
| 功能迭代 | v03-05 | 功能完善和扩展 |
| 债务清理 | v06-07 | 技术债务清理 |
| 治理+安全 | v08-09 | 流程治理和安全加固 |
| 成熟运营 | v10+ | 稳定运营和优化 |

## 模板文件

健康检查报告模板位于 `templates/health-check-report.md`，包含：
- 快照摘要
- 五维健康评分
- 识别到的债务模式
- 最高优先级行动（Top 3）
- 版本生命周期判断
- 下一版本规划建议

## 输出位置

健康检查报告输出到：`${docs}/3.analysis/diagnosis/01-active/{date}-health-check.md`

## 与其他路由的关系

- **与 aud 路由**：health-check 提供战略层面的健康评估，aud 提供代码层面的详细审计
- **与 harness-audit 路由**：harness-audit 可作为 health-check 的一个评估维度（AI 配置健康度）
- **独立使用**：可直接通过 `health-check` 或 `健康检查` 触发
