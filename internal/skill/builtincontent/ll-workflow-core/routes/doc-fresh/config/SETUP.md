# 文档保鲜系统 — 配置清单

首次使用时，系统会通过交互式问答收集以下配置。也可直接编辑 `config/document-freshness.yaml`。

## 配置项一览

### 1. 扫描路径

默认: `2.tech/`（仅技术文档）

| 选项 | 说明 |
|------|------|
| `2.tech/` (推荐) | 仅扫描技术文档，范围可控 |
| `2.tech/`, `1.task/B.todo/` | 技术文档 + 活跃任务文档 |
| 全部 `docs/` | 全量扫描（文件多，耗时长） |

### 2. 文档分类阈值

每种文档的基础过期阈值（超时后进入审计）：

| 文档类型 | 默认 | 可选 |
|----------|------|------|
| 架构文档 `architecture/` | 14d | 7d / 14d / 30d |
| API 文档 `api/` | 7d | 7d / 14d / 30d |
| 数据库文档 `database/` | 14d | 7d / 14d / 30d |
| 开发规范 `standards/` | 30d | 7d / 14d / 30d |
| 开发模板 `templates/` | 30d | 7d / 14d / 30d |
| 工具指南 `tools/` | 30d | 7d / 14d / 30d |
| 工作流 `workflow/` | 30d | 7d / 14d / 30d |
| 开发专题 `development/` (兜底) | 30d | 7d / 14d / 30d |
| 用户手册 `user_guide/` | 14d | 7d / 14d / 30d |
| 其他 `2.tech/` (默认) | 7d | 3d / 7d / 14d |

> 使用 `config.overrides` 可为单个文档指定自定义阈值，优先级高于分类匹配。

### 3. 文件级阈值覆盖

分类阈值适用于整个目录。若个别文档需要特殊处理，在交互式配置中回答追问，或直接编辑 `config.overrides`：

```yaml
overrides:
  "2.tech/architecture/02-前端架构.md": 168   # 7d，前端重构频繁
  "2.tech/api/03-Docker服务.md": 720          # 30d，Docker 配置稳定
```

| 格式 | 说明 |
|------|------|
| `"文档路径"` | 相对路径，以"天数 × 24"表示小时 |
| 如 `"2.tech/api/xx.md": 168` | 表示此文档 7d (168h) 过期 |
| `{}` | 无覆盖 |

> 交互式配置中会在分类阈值之后追加此问题。优先级：**overrides > categories 前缀匹配 > 默认值**。

### 4. 自适应阈值策略

文档连续审计通过后，自动延长审计间隔：

| 选项 | 说明 | 推荐场景 |
|------|------|----------|
| **渐进式** (推荐) | 2.0→3.0→4.0× cap | 大多数项目 |
| 倍数递增 | 2.0→4.0→8.0× cap | 信任度高的稳定项目 |
| 线性 +3d | 每次 +72h | 需要精细控制 |
| 关闭 | 无自适应 | 要求最严格的项目 |

### 5. 自适应上限

| 选项 | 效果 |
|------|------|
| ×4 (推荐) | API 最长 56d，架构最长 120d |
| ×6 | API 最长 84d，架构最长 180d |
| ×8 | API 最长 112d，架构最长 240d |

### 6. 全量审计间隔

定期忽略自适应加成，强制全量审计：

| 选项 | 说明 |
|------|------|
| 每 30 天 (推荐) | 月度全量审计 |
| 每 14 天 | 双周全量审计 |
| 每 7 天 | 最频繁 |

### 7. 单次审计上限

控制 AI API 成本：

| 选项 | 说明 |
|------|------|
| 4 个文件 | 低成本（~200K tokens） |
| 8 个文件 (推荐) | 中等（~400K tokens） |
| 12 个文件 (当前默认) | 中等（~600K tokens） |

### 8. Phase 3 Batch 最大并行

Phase 3 每个 batch 派出 4 代理（只读），控制并行 batch 数以减少 API 并发压力：

| 选项 | 说明 |
|------|------|
| 1 (推荐) | 顺序执行，稳定可靠 |
| 2 | 同时处理 2 个 batch（8 代理并行） |
| 3 | 同时处理 3 个 batch（12 代理并行） |
| 自定义 | 输入任意整数 |

### 9. 工作目录

审计系统根目录的绝对路径（交互式配置时自动检测，无需手动输入）：

```yaml
work_dir: "c:/path/to/04-auto_audit"
```

> 扫描脚本和定时任务使用此路径定位配置文件、状态文件和结果目录。

### 10. 子代理模型配置

| 角色 | 默认 | 可选 |
|------|------|------|
| 深度分析 | opus | sonnet / opus |
| 结构检查 | sonnet | sonnet / haiku |
| 快速扫描 | haiku | haiku / sonnet |
| 反面论证 | sonnet | sonnet / haiku |
| 复核 | sonnet | sonnet / opus |

### 11. 子代理语言

| 选项 | 说明 |
|------|------|
| 中文 (推荐) | 对国产模型理解更好 |
| English | 对 OpenAI/Anthropic 模型 |

### 12. 定时任务

| 选项 | 说明 |
|------|------|
| 每天 02:00 (推荐) | 凌晨低负载 |
| 每天 08:00 | 上班前完成 |
| 手动触发 | 不创建定时任务 |
| 有效天数 | 默认 30 天 |
