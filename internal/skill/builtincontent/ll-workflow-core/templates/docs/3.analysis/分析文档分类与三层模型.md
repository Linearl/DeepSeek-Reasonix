# 3.analysis 分析文档

> **分析类文档必须遵循三层模型：证据 → 诊断 → 报告。**

## 目录结构

```text
3.analysis/
├── evidence/          # 证据层：原始扫描输出、脚本记录、外部摘录
├── diagnosis/         # 诊断层：调研、现状分析、差距识别、风险清单
└── report/            # 报告层：问题修复后的复核、阶段收口、交付验收
```

## 三层模型

### 1. evidence/（证据层）

**核心规则：只放"事实"，不放"最终结论"。**

存放内容：
- 原始扫描输出（txt/json/csv）
- 脚本执行记录
- 外部摘录与引用
- 中间产物

子目录按主题或批次组织：
```text
evidence/
├── 05/               # 按批次编号
├── 06/
├── doubao/           # 按主题名称
└── README.md
```

### 2. diagnosis/（诊断层）

**目标：发现问题、识别风险、提出方案。**

存放内容：
- 现状调研报告
- 差距分析
- 风险清单
- 方案比较
- 技术评估

子目录按主题分编号：
```text
diagnosis/
├── 01-active/        # 当前活跃的诊断
├── 02-outdated/      # 已过时的诊断（归档）
├── 01-architecture/  # 架构分析
├── 02-frontend/      # 前端分析
├── 03-upload/        # 上传功能分析
└── ...
```

每个子目录含 `outdated/`，问题已解决的报告移入其中。

### 3. report/（事后分析层）

**目标：面向执行结果，需可验收。**

存放内容：
- 问题修复后的复核报告
- 阶段收口总结
- 交付验收文档
- 指标对比报告

子目录按主题组织：
```text
report/
├── architecture-remediation/   # 架构整改
├── metrics-diff/               # 指标对比
├── task-audit/                 # 任务审计
├── docs-governance/            # 文档治理
├── template/                   # 报告模板
└── ...
```

## 放置判定

| 文档类型 | 落位目录 | 说明 |
| --- | --- | --- |
| 扫描原始输出（txt/json） | `evidence/` | 仅证据，不写最终结论 |
| 事前调研、现状分析、方案比较、风险识别 | `diagnosis/` | 目标是发现问题并形成行动建议 |
| 问题修复后的复核、进展收口、提交清单 | `report/` | 面向执行结果，需可验收 |

## 命名规范

| 类型 | 格式 | 示例 |
| --- | --- | --- |
| 证据文件 | `{来源}-{日期}-{主题}.{ext}` | `scan-2026-04-01-architecture.json` |
| 诊断报告 | `{日期}-{主题}.md` | `2026-04-01-架构诊断报告.md` |
| 复核报告 | `{日期}-{主题}-report.md` | `2026-04-15-架构整改复核报告.md` |

## 维护规则

1. **证据不写结论**：证据层只放事实，结论放在诊断或报告层
2. **定期归档**：问题已解决的诊断报告移入 `outdated/`
3. **保留最新版**：同一主题只保留最新主报告，旧版归档
4. **可追溯**：报告中的结论必须能追溯到证据层
