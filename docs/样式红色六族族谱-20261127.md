## 0. 结论先行

1. 当前树的红不是「一个 --error」而是**六个来源、四个层级**：两个 token 族（`--err`/`--danger`）+ 一组 token 派生引用 + 一批历史字面值 + 一批已登记豁免位。tl1814 报告口径的六族（--err #e0696a / --danger #e5484d / #d9534f / #ef4444 / #e5534b / 亮主题 --err #dc2626）经本件逐一核树：**前两个是 token，后三个是字面值（`--status-*` token 并不存在），第六个是同一 token 的亮色档值**——「族」的正确单位是下表六行，不是六个色值。
2. 新代码遇到红色的唯一正路：**语义错误/失败提示 → `var(--err)`；破坏性操作/危险计量 → `var(--danger)`（配 `--danger-fg`）；diff 删除标记 → `var(--del-bg)/var(--del-fg)`**。禁止新增任何字面红（棘轮 + onboarding 计数钉 + swatch-sync 三道闸都在，见 §6）。
3. 字面红五组（#d9534f/#ef4444/#e5534b/#c0392b+#c0504d+#d64545 fallback/onboarding 红组）全部已有去向：前四组等 tl1814 B3/B4 批次收口（新常量或同值映射），onboarding 红组归 B5 语义对齐（计数钉已钉 12）。本件不制造任何颜色变化，归并另案拍板。

## 1. 新代码决策树（遇到「要用个红色」）

```
要红？
├─ 是「出错了/任务失败」的文本、图标、边框 → var(--err)
├─ 是「破坏性按钮/危险配额/YOLO 模式」的面 → var(--danger) + var(--danger-fg)（前景必须配对，防白字压红不达标）
├─ 是 diff 的「删除」标记 → var(--del-bg) / var(--del-fg)
├─ 是主题预览色卡 → 保持字面（swatch-sync 门禁盯着你与定义块的镜像关系）
├─ 是平台惯例（win 关闭钮/mac 红绿灯）或崩溃应急屏 → 保持字面，已在豁免清单登记
└─ 都不是 → 停。新语义先过 tl1814 命名规范（登记新 token，先登记后使用），不许裸写
```

## 8. 通俗版

界面上的红其实来自四个地方。第一类是「正规军」：两个有名字的变量 `--err`（出错提示用）和 `--danger`（删除按钮这类危险操作用），改主题只动它们的定义，全界面跟着变。第二类是「正规军的家属」：删除标记、YOLO 徽章这些，都引用上面的变量调出来的。第三类是「散兵游勇」：早期开发直接写死的五种红（协作卡、任务监控、右键菜单、几个旧组件各用各的），长相接近但改主题时它们不动——这批已经登记在施工图里等分批收编，新手引导页那 12 处也在这层、有计数器盯着不许再添。第四类是「故意写死的」：Windows 关闭钮的红、mac 红绿灯、崩溃应急屏——照抄操作系统或保命用的，永久豁免。本文件就是这四类红的户口本：以后写代码要用红，照 §1 决策树走正规军渠道；想动红的结构，先读这份再动手。
