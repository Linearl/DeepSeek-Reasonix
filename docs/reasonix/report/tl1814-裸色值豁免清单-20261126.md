## 1. 豁免五判据（tl1814 钉死，后续豁免申请照此对号）

1. **平台/OS 惯例常量**：值来自操作系统或平台官方规范，token 化反而割裂对照关系（判例：`--shadow-color` 旁的 Windows 红叉）。
2. **坏包免疫**：设计意图要求该值在主题 token 系统损坏时仍正确，必须字面常量。
3. **预览绑定**：值绑定「被预览的对象」（风格/明暗模式），不是当前主题的表面色，var 化会错乱语义。
4. **独立应急面**：主题系统之外的独立渲染面（崩溃屏），依赖 token = 失效时应急屏跟着瞎。
5. **组件本地一次性装饰**：单组件、单点、纯装饰、无跨组件复用，token 化收益低于定义+契约成本。

## 4. 棘轮基线调整建议

- **方案一（推荐，本件口径）**：棘轮维持「全量计数、只减不增」，不加豁免机制。B2–B5 执行完（收口 84 处）后，BASELINE 同 commit 下调至 **113**（= 16 既有豁免 + 97 新增豁免的天然地板）。本清单 = 该 113 处的唯一解释源；之后棘轮再降即真收口、卡在 113 即「豁免余量已到底」，语义清晰、零门禁代码改动。
- **方案二（后续独立件可选）**：给 `check-css-color-ratchet.mjs` 加键控 EXEMPT 清单（照 assert3 `HARDCOLOR_WHITELIST` 形制），基线语义升级为「非豁免裸色计数」，终值可降到 **0**，且豁免条目逐键钉死防同类膨胀。代价：门禁代码改动 + 白名单维护，属 tl1800 门禁族演进，不在本纯梳理件范围。

## 5. 遗留建议（不阻塞本件）

1. **预览色卡同步校验**：色卡值 = 定义块镜像，存在漂移风险（人工改定义忘改色卡）。可做低成本脚本比对（如 aurora 卡 accent 渐变 vs `--grad` 定义）挂 lint；收益中等，列为候选。
2. **红色族族谱清理**：现存六种红（`--err` #e0696a / `--danger` #e5484d / `--status-blocked` #d9534f / `--status-error` #ef4444 / `--status-danger-hover` #e5534b / 亮主题 `--err` #dc2626）语义重叠，值得另案设计拍板归并；本计划先如实分名登记，不制造未授权的颜色变化。
3. **onboarding 组件内混用**：B5 执行时顺带在组件头部留一行注释说明「accent 派生值随主题」的约定，防回归。
