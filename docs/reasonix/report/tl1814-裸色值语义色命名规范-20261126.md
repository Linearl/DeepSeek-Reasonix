# 裸色值语义 token 命名规范（tl1814）

> 生效：2026-11-26。适用：tl1800 遗留 181 处裸色值收口的全部后续批次（B2–B5）。
> 性质：命名注册表 + 执行纪律。后续批次新 token **先在本文件登记再使用**，防命名漂移。
> 配套：`tl1814-裸色值六组分批计划-20261126.tsv`（逐站点 token 指派）、`tl1814-裸色值豁免清单-20261126.md`。

## 1. 总则

1. **kebab-case，全小写**，段间用 `-`。禁 camelCase、禁下划线、禁缩写（`--bg-elev` 级别的既有缩写除外，沿用不扩展）。
2. **语义优先于色相**：token 名回答「这是什么的颜色」，不回答「这是什么颜色」。色相名仅当语义本身就是「按色相区分的并列类别」（如 context-panel 的 source-tone 色板）时允许，且须挂组件前缀（`--ctx-slate`）。
3. **禁止值命名**：`--gray-400`、`--red-500` 式槽位名一律禁止——值可以改，名不能骗。
4. **定义值 = 被替换的原裸值**（新常量路线 C 的铁律；声明式微差路线 B 除外，见 §5）。
5. **组件独占值挂组件前缀**：仅一个组件使用且无跨组件语义的，用 `--ctx-*`/`--im-*`/`--onboarding-*` 式前缀，不进全局语义命名空间；两个以上组件共用或表达全局状态语义的（`--status-*`、`--ok-strong`），用全局名。
6. **不与既有 token 同名异值**：新名落笔前先查 `styles.css :root` 与 `check-theme-token-contract` 的 requiredRootTokens；IM 平台色已有 `--brand-feishu=#2f80ff`（官方品牌值），chip 用近似色板值 #0ea5e9 属另一语义，必须另起 `--im-*` 族，禁止复用 `--brand-*` 名。

## 2. 既有族口径（14+ 族对齐基准）

| 族前缀 | 语义 | 本计划相关 |
|---|---|---|
| `--bg / --bg-soft / --bg-elev / --bg-elev-2` | 底色阶梯 | 亮面/画布新常量不得冒用此族（值不等） |
| `--surface / --surface-2 / --surface-3 / --surface-white` | 面阶梯 + 恒白面 | 新增 `--surface-fixed-light` 同挂 surface 族 |
| `--text / --text-2 / --text-3 / --text-on-color` | 文字阶梯 + 彩面恒白字 | |
| `--fg / --fg-dim / --fg-faint` | 前景阶梯（text 的实体层） | |
| `--accent / --accent-fg / --accent-strong / --accent-soft` | 主题强调色族 | B5 onboarding 归并目标 |
| `--ok / --warn / --err / --danger` | 状态语义四色 | 徽标边色同值映射目标；新状态色挂 `--status-*` |
| `--brand-feishu/qq/lark/weixin` | IM 官方品牌色 | 与 `--im-*`（近似色板）严格区分 |
| `--shadow-color / --scrim-color / --shade-color / --highlight-color` | 明暗机制四色（tl1800 钉契约） | B2 同值映射目标 |
| `--chart-* / --hl-* / --z-* / --r-* / --mode-* / --list-* / --tree-* / --button-* / --control-* / --pill-*` | 领域族 | 本计划不触碰 |

## 4. 后缀语义（复用既有判例，不发明新形态）

| 后缀 | 语义 | 先例 |
|---|---|---|
| `-deep` | 同族深档（配对值，用于文字/边） | 本计划 `--im-*-deep`（对齐 500/600 色板惯例） |
| `-hover` | hover 态专值（仅当 color-mix 深化非同值时才允许设此缀） | 本计划 `--ok-strong-hover` |
| `-muted` | 弱化/降饱和档 | 本计划 `--ctx-*-muted` |
| `-strong` | 同语义更强/更饱和档 | 既有 `--accent-strong` |
| `-fixed` | 不随主题的恒定值 | 本计划 `--surface-fixed-light` |
| `-on-color` / `-white` 等既有缀 | 沿用原语义，不扩展新含义 | `--text-on-color` |

## 5. 路线决策树（每个站点按序问，命中即停）

```
A 同值映射既有 token   —— 值精确相等（含 color-mix 预乘等价）→ 直接替换，零风险
C 新常量（定义值=原裸值）—— 值不等但语义独立成族 → 新 token，组件独挂前缀
B 声明式微差           —— 归并既有 token 可修复语义缺陷/减常量，ΔRGB 全部列出
                          + 基线主题截图对比 + 影响面写明 → 才许动手
D 豁免                 —— 命中豁免判据（见豁免清单文件五判据）→ 留计数+登记
```

路线 B 的三道闸（缺一不可）：ΔRGB 逐站点列明；≥1 张基线主题前后对比截图；非基线主题行为变化写进 commit message。

## 6. 防漂移纪律（每批执行时逐条打勾）

1. 每批一个 commit；棘轮 BASELINE **同 commit** 下调（脚本输出会提示收紧值）。
2. 新 token 定义进 `:root` 固定区（tl1800 主题不变常量块），并加进 `check-theme-token-contract` 的 `requiredRootTokens`（与 --shadow-color 同待遇）。
3. 替换后跑 `check:theme-token` + `check:class-contract`（assert3 拦新键）+ `check:color-ratchet` 三门禁全绿才算完。
4. 同值替换（A/C）逐站点机检：替换前后 computed color 字节等价；路线 B 另附截图。
5. token 名未在本文件 §3 登记的，不得出现在 diff 里（先登记后使用）。
6. 批次顺序固定 B2→B3→B4→B5（先零风险后声明微差）；B6 豁免登记不触代码。

## 7. non-goals

- 不合并既有六种红色（--err/--danger/#d9534f/#ef4444/#e5534b/#dc2626 族谱清理）——值变化面大，另案设计拍板。
- 不动主题定义块内部（`data-theme-style` 各块的字面量是合法定义行，棘轮不计数）。
- 不给棘轮脚本加豁免 allowlist（可作为后续独立件；本计划采用「留计数+登记」口径）。
- 不做预览色卡与定义块的同步校验门禁（列为遗留建议，见豁免清单 §4）。
