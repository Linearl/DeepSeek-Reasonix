## 问题① 强制终止无效（命令类任务跑 2h10m 点停止无效）

### 判断

**装机路径所致，main 已闭环，无真缺口。** 用户实测场景涉及两条相互独立的停止链：

**链 A：turn 级（Composer 停止按钮）——P7 覆盖前台命令/工具卡死**

- 路径：`App.CancelStopForTab` → `Controller.CancelStop`（`internal/control/stop_escalation.go`）→ L1 优雅取消（30s 无应答自动升级，ruling ④）→ L2 15s 强制宽限（ruling ②）→ L3 强制（`forceCancel` 执行器弃管 watchdog + turn cancel，前台命令经 `CommandContext` + `SetCancelKillsTree`/Job Object 杀进程树）。
- 0119 无 P7 → 点停止只有一次 L1 优雅取消，卡死的命令不退出 → 「点停止无效」。**已修待装机**。

**链 B：后台任务级（命令类后台作业 = jobs：bash/task/fleet 三类启动方）——独立于 P7**

- 路径：任务胶囊停止（440b）→ `App.CancelJobForTab` → `Controller.CancelJob` → `jobs.Manager.KillForSession` → `j.cancel()` → 作业内 `proc.CommandContext(jobCtx)` 触发杀树（Windows：`StartTracked` Job Object `KILL_ON_JOB_CLOSE` + `taskkill /F /T` + `TreeTracker` 兜底，`internal/proc/`）。task/fleet 作业的 run 均把 jobCtx 传入子代理会话，取消可传导。
- 关键语义：**jobs/enroll 任务链的停止不走 P7 升级链，P7 的 turn 取消也不停后台任务**（设计如此：后台任务跨轮存活）。0119 无 440b 胶囊「按来源停止」→ 用户对后台任务没有停止入口，点 turn 级停止自然无效。**440b 已补入口，待装机**。

### 修法

无（main 两链均已闭环）。

### 装机后验证步骤

1. **turn 级**：让 agent 前台跑长命令（如 `sleep 3600`）→ 点一次停止 → ≤30s 自动开 L2 宽限（UI 倒计时）→ 倒计时归零或再次点击触发 L3 → 进程树死亡、UI 立即释放。
2. **后台任务级**：agent `run_in_background` 起长命令 → 任务胶囊出现 → 点胶囊停止 → 任务即时置 Killed（状态同步翻转，不 等 WaitDelay）、进程树死亡。
3. 跑长构建的会话可调大 `stopAutoGraceAfter`/`stopForceGrace`（代码 vars，ruling ⑦）避免误升级。

## 问题② 上下文长度异常 + 压缩失败

### 判断

**a) 单轮无界增长点——逐项排查：**

| 候选 | 结论 |
|---|---|
| P9 工具间隙注入 | 0119 无 P9（10-04 00:29 才合），非实测原因；P9 走 `TrySteerInboxItem` 既有通道，接受即消费、拒绝留队，无自动批量注入面 |
| 工具输出累积 | 单条结果回灌前有 32KB 硬上限（`maxToolOutputBytes`，tool-aware 裁剪）+ 同文去重 + read 预算二次裁剪——单条有界 |
| 检查盲区 | 无：每次模型采样请求前都跑 `Prepare`（`buildSamplingRequest` → pressure 检查），物理超窗另有一次性 overflow 恢复（`prepareSamplingRequest`） |
| **真异常增长源** | **重放风暴喂养（与问题③同源）**：泵每 5-6s 重投重复引导消息 → 入收件箱 → 消费注入上下文 → 重复累积；加上长任务正常多轮增长压缩追不上 |

**b) 压缩触发与失败路径：** 0119 已含三道已知修复——#9572（08-29，自动摘要请求 cap 在配置窗口内）、GLM 1261 无 token 超窗解析（09-07，`unnumbered overflows`）、Task 307（09-27，checkpoint ceiling 首拒即截断，杜绝「3.8M tokens 三连拒不救援」先例）。阶梯摘要（pressure ≤2 次 / manual 超顶 4 批次）+ 截断救援 + stuck 回退完备。实测观感的「压缩失败」更可能是：重放持续喂养导致**压缩追不上**（非压缩本身失败）+ 巨大 region 的摘要多轮尝试耗时被感知为失败；「强退重启后花费大量资源压缩」= 重启全量载入（含全部重复消息）→ 一次性巨大摘要请求。

**c) 诊断入口与防线：**

- 已有入口：`ContextMaintenanceReceipt`（blocked/failed 持久化 + 事件）、compaction telemetry、Context Panel（ProjectedTokens/FoldTrigger）、slog。
- **本次新增**：单轮增幅观测告警（`observeContextGrowth`，`internal/agent/context_manager.go`）——每次维护检查记录估算增量，一次维护间隔内增幅 ≥ 窗口 40%（`contextGrowthWarnRatio`）即 `slog.Warn`（含 prev/now/delta/window/turn），同轮去重 + 5 分钟冷却重臂。纯观测，零行为变化，给「上下文异常增长」一个具名日志诊断入口。
- **自动熔断暂不做**：压力压缩 + overflow 恢复 + Task 307 截断已是行为层熔断；无差别拒绝增长会误伤长读任务（大文件审计场景）。建议装机后先看告警日志分布再定熔断阈值——若告警集中在重放场景，P10 断根后应自然消失。

### 修法

`observeContextGrowth` 增幅观测告警（见上）+ 3 组真断言测试（`context_growth_warn_test.go`：跳变触发/同轮去重新轮重臂/退化为零输入静默且不动基线）。

## 问题③ 引导消息重放复验

### 判断

1. **主因 = 0119 无 P10**：实测死循环链（P10 commit `38fe568c6` 证据：desktop.log 每 5-6s 一次 `inbox_idempotency_conflict`，16 组、同句×12、173s）——泵内容键命中同 key、信封指纹含重发新 msg id → conflict → 不 ack 每周期重投 + 投递失败通知喂养发送方重试。**装机即断根**。
2. **复验发现一处独立真缺口（本次已修）**：task 309 设计为「idempotency default-on」（commit `0df5fdb2b` 标题、字段注释、render 文案三处宣称 on），但 `Default()` 零值实际 **false**——全新默认环境内容键去重不生效，发送方换新 msg id 重发会**真重复入箱**（P10 静默 ack 断了通知喂养环，但没堵住这个无键重复的尾巴）。用户环境 `config.toml:175` 已固化 `true`（render 写盘）不受影响；本次把 `Default()` 钉为 `true`（与文档语义一致），用户显式 `false` 仍可关。测试锚定（默认真 + 显式假解码不被覆盖）。
3. **其余重放源排查为阴性**：pump 真失败保留 pending 重试（同 msg id 同键，sessioninbox 幂等挡重复，非重放源）；`trySteerInboxItem` 消费结算 admission 先持久化 + 已 admitted 幂等短路，无「注入成功但不结算」窗口；`ReplayPendingPrompts` 是 approval/ask 重放，与引导消息无关。
4. **DAG 调研报告「LoadSession 族静默全量解码循环」与重放不同源**：那是 save-path 互斥锁被搜索收集/话题标题/历史页回退等 `LoadSession` 全量解码占满的性能问题（589MiB 会话约 2 次全量解码/分钟、锁内各 25-30s、锁等待 p50=28.1s）；重放是语义重复投递。间接关联仅一层：重放消息写入会话日志会加大全量解码的量，但机制与根因不同——P10 断根不会缓解锁竞争，两者需分开治理（锁竞争治法见 DAG 报告：LoadSession 族增量解码/缓存化）。

### 修法

`Default()` 补 `SessionCollabMailIdempotentDefault: true`（`internal/config/config.go`），恢复 task 309 既定语义。

### main tip 预存红 handoff（基线 `0849f7d46` stash 对照证实，非本切片引入）

agent 包在本机存在两类预存红，均与 DAG 重放/文件锁域同源，建议归 DAG 治理线一并处理：

1. **真死挂**：`go test ./internal/agent/ -run TestAppendForShutdownWithoutLockAfterTornTail` 27 分钟无进展。栈：`AppendForShutdownWithoutLock → appendUnlockedLocked → sessionDAGState.replayFrom → resumePastTornLine → replayFrom` 互调后卡死——torn tail 后 shutdown 追加触发重放越过洞，重放循环无进展保护（死循环或无界等待）。同族 `TestReplaySkipsTornLineBetweenEntries` 单跑同样 7 分钟+不归。
2. **断言失败**（单跑稳定复现）：`TestWithContextBudgetPrefixesAndSkips`（budget block 缺失）、`TestReadOnlyWanderingTripsTheProgressGuard` / `TestRepeatedReadTripsTheProgressGuard`（41 轮未触发 no-progress 阶梯）。

以上均在基线（stash 本切片全部改动后）复现，切片排除这些预存件后相关测试全绿。agent 包整包测试需先修复上述预存红才能作为门禁（P7 切片当时包级全绿的结论在不同子集/环境下得出，此处如实记录当前状态）。
