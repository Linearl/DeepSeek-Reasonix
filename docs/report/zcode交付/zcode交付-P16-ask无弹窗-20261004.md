## 1. 核查①：前端 ask→AskCard 事件链，何况不弹

**正常链**（全部 synchronous/顺序化，逐环可查）：

```
model 调 ask 工具（internal/agent/ask.go Execute）
→ Controller.Ask（internal/control/controller.go ~2824）
   registerAsk（排队登记，queued=true）→ lockPromptFor（等 promptMu）
   → EmitChecked(AskRequest)（带 turn id 绑定）→ markAskEmitted（转可重放）
   → log "[ask-panel] ask request emitted"（428）
→ goalUsageTee → tabEventSink.Emit（desktop/tabs.go）
   → toWireTabWithSubmission（本切片起盖 emittedAt 锚）
   → asyncRuntimeEmitter 队列 → runtime.EventsEmit（单 webview 通道）
→ 前端 reducer case "ask_request"（useController.ts）
   → 本切片起先落收据行 reportAskPanelReceipt
   → judgeAskArrival（428 门）→ beginPromptWait（state.ask 置位）
→ decisionSurface="ask" → DecisionFooterRegion → AskCard 挂载（本切片起落挂载行）
```

**不弹路径清单（现链路残面）**：

| # | 路径 | 现状 |
|---|---|---|
| a | 后端 emit 失败 | 返回错误 turn 终止 + `[ask-panel] ask request emit failed`（428），不可能静默 |
| b | emit 成功但前端没收到（通道丢/页面重载窗口） | 有 `ask received` 收据行缺失即暴露；重连/换页有 ReplayPendingPrompts + `replayPendingPromptsForActiveTab` 主动重放兜底 |
| c | 收到但 reducer 丢弃 | 仅两处可证明正当（已作答墓碑 / cancel 后 turn 真落定），428 门 + verdict 打点；C1/C2 吞没已修 |
| d | reducer 置位但不渲染 | `runtimeTransitioning`（导航过渡）期间 `visibleDecisionSurface` 暂时为 null，过渡结束恢复——**暂态**，不构成永久不弹 |
| e | ask 排队在前一 prompt 之后 | queued ask 不 emit 也不进快照，只有 `NoticeCodePromptQueued` 提示——若提示也丢则**完全无 UI**，这是「完全没出现任何提问 UI」的最贴合形态；终止第一击可打断（见核查③测试 2） |
| f | 挂载即崩 / CSS 遮蔽 | AskCard 组件无自遮蔽条件（渲染即可点）；本切片挂载行可证达到渲染层 |

**相邻发现（未动，留 P17/后续）**：reducer `mcp_interaction` 分支仍是 428 之前的旧形态 `if (s.cancelRequested) return s`（残留 cancel 一律丢弃、无打点）——与 C1 同形的坑，属 MCP 卡片不属于 ask，本切片不改不锚，报告留档。

## 2. 核查②：`c.autopilot` 判据 vs Yolo/auto 姿态

- **取值**：`controller.go:824/831` `autopilot: opts.Autopilot && opts.AutopilotMaxRuntime > 0`——仅入口级 autopilot 开关且必须配了 max-runtime。
- **桌面门（task 325）**：`desktop/autopilot_gate.go`——autopilot 仅在 yolo 审批姿态可开（`autopilotGateAllowed`），离开 yolo 自动关闭（`closeAutopilotForOffYolo` 反向联动）；新标签/恢复/设置四入口同门。**yolo 姿态本身不等于 autopilot**：没开 autopilot 偏好的 yolo 会话 `c.autopilot=false`。
- **task 283 unattended 家族**：`internal/agent` 层（`turn.unattended = a.autopilot || toolRecoveryExempt(ctx)`，run_loop.go:81），只影响 readiness 门与工具恢复围栏；**没有**回灌 controller 的 ask 等待分支。
- **ask 与 yolo 的关系**：`Controller.Ask` 注释与 ask 工具描述明确「Ask is NOT bypassed in YOLO mode」——yolo 只自动批工具调用，不代答用户问题。非 autopilot 会话（含 yolo）ask 无限等 reply 是**设计行为**（用户在场）。
- **H2 终判**：若该 yolo 会话真开了 autopilot，低风险 ask 会被 `autopilotAnswers` 自答（无弹窗但有 transcript 审计记录，task 49 A3）、高风险 ask 等 `DefaultAutopilotAskWait`=10min 后终态停止（task 109 B4，`internal/control/ask_risk.go:38`）——**都不产生「无限阻塞」**，与现场不符。结合现场「turn 长期卡死」，H2 排除，断点在前端投递半段（H1）。

## 3. 核查③：P7 三级终止对 ask 等待 turn 的覆盖

**链路**（现 main-v2-stable）：

- `CancelStop` L1 → `cancelTurnLocked`（cancel.go:23）：先 `cancel()`（turn ctx）→ `promptOwner.CancelAll()` → `approval.clearAll()`（挂起 ask 撤出快照）。
- ask 等待三路 select（`reply` / `askTimeout`（仅 autopilot）/ `waitCtx.Done()`）：`waitCtx` 派生自 ask 工具的调用 ctx，后者派生自 turn ctx → **L1 即解阻塞**，Ask 返回 `context.Canceled`，turn 收尾。
- 排队态（`lockPromptFor` 等 promptMu）：ctx.Done 分支返回 false + 异步释放锁，同样解阻塞。
- 保底升级：L1 后 30s 无确认自动开宽限（ruling ④）→ 15s 倒计时 → L3 force（执行器 abandon watchdog）。
- 终止后 `clearAll` 已撤快照 → 重连重放**不会复活死问题卡片**（0119「终止后仍卡死」的反向面）。
- 前端一致性：`turn_status: cancelling` 会清掉 ask 卡片并锁存 cancelRequested；若 ask 真已被取消而 turn 迟迟不落定，428 门按「cancel 残留 + turn 存活」放行后续新 ask。

**缺口**：P7 既有测试只压「忽略取消的假 turn」，ask 既有测试只压裸 ctx cancel——**真实 ask 等待 × 停止按钮入口的交叉没有钉子**。本切片补齐（见 4.1）。

### 4.2 投递链打点（desktop/tabs.go + 前端四文件）

- **wire `EmittedAt`**（`wireEventTab`，`json:"emittedAt,omitempty"`）：`toWireTab` 唯一出口 `toWireTabWithSubmission` 盖后端序列化时刻（unix ms）。加法字段：旧前端忽略，重放事件自带重放时刻。

## 5. 与 P17 的联合定位互引

三症状同判据：**同一后端→webview 单通道**（`asyncRuntimeEmitter` + Wails EventsEmit）。本切片落的两件公共设施 P17 直接可用：

1. 每条事件自带 `emittedAt`——P17 在用户消息提交回执/turn 事件路径加同样的 `delivery_ms` 收据行，即可量化「后端已收前端不渲染」的断点；
2. 队列积压告警不分事件种类——若三症状同时段出现告警，即坐实共享通道拥塞（与 DAG 调研 LoadSession 持锁 25-30s 的慢路径对时）；无告警而 delivery_ms 大，则断点在 webview/JS 侧。

先例互引：memory「交付验收框间歇性不出现根因-ctx时效竞态-2026-08-31」（同类「后端事件→前端呈现」时效竞态模式）。

1. **Yolo ask 弹窗回归**：Yolo 会话让模型调 ask → 卡片应弹出；desktop.log 应依次出现 `ask request emitted` → `ask received … delivery_ms=N` → `ask card mounted`。
